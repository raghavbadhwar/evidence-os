# Evidence OS pilot audit

**Decision.** Test the lawyer plus the system on scoped, calendar-day termination questions. The best reason to run the study is a retrieval failure that changed answers in the comparison fixture. The largest open risk is a credible-looking answer that quotes the amendment and overlooks a narrower exception. Independently grade that error even when the citation is accurate.

## What ran

From the isolated pin, with the existing environment's Python and `PYTHONPATH=src`:

| Command | Observed |
|---|---|
| `python -m benchmarks.first_time_notice` | [Output](eos-first-study.json). 6/6 expected periods or abstentions, 1 execution abstention, 24/24 annotated passages returned. |
| `python -m benchmarks.first_time_notice --baseline` | [Output](eos-base-study.json). 4/6 correct, 0 period abstentions, 12/24 passages. This is the old retrieval route with a scripted reasoner. It is a different comparator from lawyers using their usual tools. |
| `python -m benchmarks.evidence_qualification` | [Output](eos-qual-study.json). Across eight cases, all decisive evidence in 1/2 retrieval tasks, 2/2 supported comparisons, 4/4 expected abstentions, 0/8 unexpected releases. The fixture author supplied the rule. |
| `python -m pytest -q tests/evidence` | 21 passed, six dependency deprecation warnings. Includes review lifecycle, rejected unknown IDs and conflicting support, and no partial dispatch on overflow (tests/evidence/test_first_time_notice.py:45–147). |

The six first questions reuse two near-identical four-document packets. The 24 entries count all four fixture passages per question, including a draft, even for a pre-amendment date. They do not represent 24 independent controlling exceptions. The scripted reasoner parses fixed phrases and copies the requested route into relationships. Its verifier always returns “supported.” The release counter tests whether a pre-review response contains a released statement. It cannot measure wrong approvals. Both first-review routes made zero hosted calls. Repeats before lawyer approval exercise another request, not approved-rule reuse. Timings exclude ingestion and human work. See benchmarks/first_time_notice.py:23–102,153–180,221–249,267–284 and benchmarks/evidence_qualification.py:26–39,111–151.

## Local pilot change after the audit

The study branch adds a workspace form after lawyer approval. The reviewer enters the effective interval, confirms conditions, selects source passages and records the basis for reuse. Saving from the approved finding requires every cited controlling ID. The existing review API still owns authorization and snapshot validation. The hypothetical now displays the result with source links. A lawyer who disagrees can reject the finding, rerun with corrected scope or use the existing reviewed-rule API. The broader API coverage limitation above still applies. Freeze the exact study build and train staff on the manual route before timing.

The new form submits the reviewed assessment ID. The server checks its current approval, model revisions, party, route, minimum and inclusion of all controlling citations in the same transaction as rule promotion. Standalone lawyer-authored rules continue through the earlier API. The study build extends tests/evidence/test_first_time_notice.py to reject removal of the unlinked side letter, a substituted party and a second promotion from an invalidated finding.

For a local installation follow [workspace setup](../evidence-workspace.md). From the repo root, initialize once with `python -m proofcounsel_ingest.evidence init`, then run `python -m proofcounsel_ingest.evidence serve` in the configured environment and open the loopback workspace on port 8765. Use the local reviewer identity. For the new path choose **Review contractual notice**, inspect the source passages, approve the finding, then fill **Approve a reusable notice rule**. The saved rule appears under **Reviewed notice rules**. During the real-file study use only the approved deployment.

Post-change verification: the complete local suite (`PYTHONPATH=src python -m pytest -q`) reported 182 passed, four live PostgreSQL checks skipped and six dependency warnings. Headless Chrome against the local HTTP application with the scripted synthetic provider exercised first review, approval, rejection of incomplete source selection, saving the signed-side-letter rule, a 35-day hypothetical with citations, and an unresolved answer immediately after a new amendment was registered. The existing post-ingestion stale-rule test also passed (tests/evidence/test_workspace.py:142–164). These checks used no client data.
